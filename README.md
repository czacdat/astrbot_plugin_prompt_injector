# 生图提示词注入（astrbot_plugin_prompt_injector）

给 `generate_image` 的提示词**在最前面自动加一段固定前缀**（画师词、质量词），
**不修改生图插件源码，也不经过对话模型**。

---

## 解决什么问题

用 `astrbot_plugin_image_generation` 时，模型每次写的提示词质量参差不齐：
有时记得带 `masterpiece, best quality`，有时忘得干干净净。
想稳定加上去，通常只有三条路：

| 做法 | 问题 |
|---|---|
| 在人格里叮嘱模型 | 靠模型记性，浪费 token，还会忘 |
| 改生图插件源码 | 插件一更新就没了 |
| 用提示词模板 / 预设 | 每次生成都得手动选 |

这个插件走第四条：**在工具调用层拦截参数**，把前缀直接拼进 `prompt`。
模型看不到、也不需要知道，**零额外 token**。

---

## 工作原理

```
模型决定调用 generate_image
        ↓
插件拦在工具执行之前（猴子补丁）
        ↓
改写 kwargs["prompt"] = 前缀 + 分隔符 + 原提示词
        ↓
交给生图插件原本的实现
```

实现方式：

1. 从 AstrBot 的工具管理器里找到名字等于 `target_tool`（默认 `generate_image`）的工具；
2. 给它**所属的类**打补丁，替换 `call` 方法；
3. 每次调用先改 `kwargs["prompt"]`，再交给原始实现；
4. 后台每 5 秒检查一次，处理「生图插件后加载」和「插件被重载导致补丁丢失」两种情况。

> 补丁失败、或注入过程出现任何异常，都会**按原样执行**，不会让生图失败。

## 安装

把整个目录放到：

```
<AstrBot 实例>/data/plugins/astrbot_plugin_prompt_injector/
```

然后在面板里重载插件（或重启 AstrBot）。

加载成功后日志里会出现：

```
[PromptInjector] 已拦截工具 generate_image（类 ImageGenerationTool），当前前缀: masterpiece, best quality
```

如果只看到第一行、没有第二行，说明生图插件还没加载 —— 等 5 秒会自动补上。

## 配置项

面板路径：`插件管理 → 生图提示词注入 → 配置`

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 总开关。关掉后不再注入，配置保留 |
| `prefix` | text | `masterpiece, best quality, very aesthetic` | 固定前缀。**留空等于不注入** |
| `separator` | string | `, ` | 前缀与正文的分隔符 |
| `target_tool` | string | `generate_image` | 要拦截的工具名，一般不用改 |
| `dedupe` | bool | `true` | 防重复注入：开头已有前缀就不再叠加 |
| `whitelist_groups` | list | `[]` | 群号白名单。**留空 = 所有群和私聊都生效** |
| `log_injections` | bool | `true` | 每次注入都记一行日志，便于排查 |

**改完立刻生效，不需要重载插件**（每次注入前会重新读一次配置）。

## 聊天命令

唤醒前缀为 `/` 时：

```
/注入前缀                     查看状态（所有人可用）
/注入前缀 开启                 开启注入
/注入前缀 关闭                 关闭注入
/注入前缀 设置 <内容>          改前缀并自动开启
/注入前缀 白名单 <群号>        添加白名单（可一次写多个）
/注入前缀 移除白名单 <群号>    移除
/注入前缀 清空白名单           清空（恢复全局生效）
```

**权限规则：**

| 场景 | 行为 |
|---|---|
| 白名单为空 | 所有会话都能查状态；改设置需要管理员 |
| 在名单内的群 | 正常响应；改设置需要管理员 |
| 不在名单的群 | **完全静默**，不回复任何内容（连「有这个插件」都不暴露） |
| 私聊 | 只有管理员可用（避免把自己锁在外面） |

## 注入规则

```
prompt 为空      → 只发前缀
prompt 已有前缀  → 不重复加（大小写不敏感）
prompt 是 None   → 补成前缀
前缀为空         → 完全不注入
非字符串 prompt  → 原样放过
```

举例（前缀 `masterpiece, best quality`）：

| 原提示词 | 实际发送 |
|---|---|
| `1girl, solo` | `masterpiece, best quality, 1girl, solo` |
| `masterpiece, best quality, 1girl` | 不变（防重复） |
| `MasterPiece, Best Quality, 1girl` | 不变（大小写不敏感） |
| （空） | `masterpiece, best quality` |

## 常见问题

**Q：改完面板不生效？**
A：这个插件每次注入前都会重读配置，正常是立刻生效的。
如果没生效，检查 `enabled` 是否被聊天命令关过（以最后写入的为准）。

**Q：为什么日志里没看到注入，图还是带前缀了？**
A：看生图任务记录里的 `prompt` 字段才是准的 —— 「使用工具：generate_image，参数：…」
那行日志打印的是**模型原始参数**（注入前），所以看起来没有前缀。

**Q：会不会和生图插件的「预设」「人设」冲突？**
A：不会。前缀加在最终 `prompt` 最前面，预设/人设的拼接仍由生图插件负责。

**Q：会不会重复加两次？**
A：默认开启防重复。即使连续调用两次，第二次检测到开头已有前缀就会跳过。

**Q：能用来看别的工具吗？**
A：可以，但要看那个工具是怎么注册的（v1.0.2 起两种都支持）：

| 工具类型 | 怎么打补丁 | 例子 |
|---|---|---|
| 自定义 `call` 的类 | 替换类的 `call` | `generate_image`（生图插件） |
| `@filter.llm_tool` 注册 | 只替换这个实例的 `handler` | 大多数插件的工具 |

两种都不属于的话，日志会明确报「既没有自定义 call 也没有 handler」，不会假装成功。
另外只有带 `prompt` 参数的工具才值得注入。

## 已知限制

- **只影响工具调用**：如果生图是通过插件自己的命令（如 `/生图 xxx`）触发、且不经过 `generate_image` 工具，则不会被注入。
- **模型不知道前缀**：它是注入之后才拼上去的，所以模型在文字里描述「我用了什么词」时不会包含前缀。
- **依赖生图插件的工具名**：插件改名或换插件时需要同步改 `target_tool`。
- **白名单是严格匹配**：群号必须完全一致，不会因为前缀相同就命中。
